## Findings and fixes

### Literal NA metadata in the legacy VCF table

`read.vcf()` previously converted every output field equal to the text `"NA"` into an R missing value. This incorrectly affected valid chromosome names, variant IDs and allele text. The conversion is now restricted to missing genotype placeholders produced by converted genotype modes. `genotype="None"` retains HTSlib-formatted text without this conversion. `vcf2matrix()` already preserved metadata correctly.

The new VCF fixture contains a chromosome, variant ID and REF allele literally named `NA`, plus missing and called genotypes. The test checks all four legacy display modes and the direct integer-matrix reader. It failed on the preceding installation and passes after the fix.

### Figure dimensions, scaling and custom devices

`savefig()` ignored `scale`, treated PDF dimensions as inches regardless of the requested units and rejected a device function even though its interface documented that option. It now applies scaling, converts physical/pixel sizes consistently and supports custom functions. Built-in raster device functions receive the same resolution and units as their named equivalents. Custom functions receive dimensions in inches and must accept `filename`, `width` and `height` and open a device.

Width and height default independently; sizes, scale and DPI must be finite positive scalars. After drawing, including a drawing error, the output device is closed and the previous device is restored if still available. The tests inspect actual PNG dimensions, PDF page dimensions, custom-device arguments and device cleanup. The scaling test failed before the fix. API documentation describes the unit convention explicitly.
